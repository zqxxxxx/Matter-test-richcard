# AGENTS.md 防串改规则模板

把下面内容复制到项目的 `AGENTS.md` 中，可作为所有项目的通用开发约束。

```md
## 防串改与回归约束

任何代码改动前，必须先明确：

- 本次目标
- 允许改动范围
- 禁止改动范围
- 可能受影响的共享链路

涉及以下内容时，自动视为高风险改动：

- 共享组件
- 消息、通知、同步链路
- 状态聚合、adapter、公共 utils
- 路由、登录态、权限
- 缓存、构建、部署配置
- 后端公共 service、handler、middleware
- 数据模型、数据库迁移

高风险改动必须先补充或运行保护测试，再修改实现。验证不能只覆盖当前需求，还必须覆盖相邻业务和共享链路。

开发顺序：

1. 复现问题或确认现状。
2. 写清影响面清单。
3. 补充或选择保护测试。
4. 修改实现。
5. 跑窄范围测试。
6. 跑相关链路回归。
7. 部署后验证线上实际版本和实际行为。

测试数据必须使用固定前缀：

- `[SMOKE]`
- `[QA]`
- `[REGRESSION]`
- `[DO-NOT-DELETE]`

禁止生成看起来像真实业务的数据。清理数据时只能清理带测试前缀的数据。

交付说明必须包含：

- 本次改动
- 直接影响
- 潜在影响
- 明确未改
- 测试命令和结果
- 部署版本或构建产物
- 线上验证结果
- 未覆盖风险

如果出现“修 A 坏 B”，必须暂停新增功能，先定位共享链路、最近改动和缺失测试，再做最小修复。
```
